# Noctalia 锁屏解锁延迟修复

记录锁屏后输入密码需等待约 10 秒才能进入桌面的问题诊断与修复。

## 问题

锁屏后输入正确密码，需等待约 10 秒才回到桌面。

## 诊断结论（2026-08-15）

锁屏链路：`hypridle` → `noctalia-shell ipc call lockScreen lock` → quickshell 的
`WlSessionLock`（noctalia-shell 内置锁屏，非 swaylock）→ quickshell PAM 子进程认证 → niri 解锁会话。

三次真实解锁的 journal 时间戳（`journalctl --user -u noctalia-shell`）显示 10 秒全部消耗在 PAM 认证阶段，niri 在认证完成的同一毫秒即
`unlocking session`：

```
11:27:42  提交密码
   +3.5s  unix-early 探测（pam_unix nullok 空检查也要验证哈希）
   +7.0s  pam_gnome_keyring 解密 login keyring
   +7.0s  pam_unix 再验证两次（likeauth + try_first_pass）
11:27:53  PAM 完成 → niri: unlocking session
```

根因分解：

1. **锁屏使用完整的 `/etc/pam.d/login` 栈**（noctalia 默认），该栈为 greetd/登录设计：
   - `unix-early`（`optional ... likeauth nullok`）：即使密码还没输入也会做一次哈希探测，实测 3.55 秒（隔离实验：单条
     `pam_unix.so nullok`，T+3536ms 才弹出 Password 提示）
   - `pam_gnome_keyring`：用密码解密 login keyring，实测约 3 秒
   - `pam_unix sufficient ... try_first_pass`：再次验证密码
2. **密码哈希成本过高**：`initialHashedPassword` 使用 `scrypt rounds=11`（`$7$`
   前缀），单次验证实测 1741/1771/1748 ms。栈中每次 pam_unix 运行都要重新计算。

quickshell 源码确认（`src/services/pam/subprocess.cpp`）：PAM 子进程只调用 `pam_start_confdir` +
`pam_authenticate` + `pam_end`，不运行 account/session 阶段。

社区佐证：noctalia 官方支持 `NOCTALIA_PAM_SERVICE` 环境变量指定锁屏 PAM 服务（`LockContext.qml`
读取该变量）；同类做法见 quickshell 官方 lockscreen 示例与社区 gist（allmeta/f52b6619）。

## 修复（2026-08-15）

### 1. 专用锁屏 PAM 服务（已实施）

- `modules/nixos/desktop/security.nix` 新增
  `security.pam.services.noctalia-lock`（仅一次 pam_unix 校验，无 nullok 探测、无 gnome-keyring）
- `home/linux/gui/base/noctalia/default.nix` 的 noctalia-shell.service 注入
  `NOCTALIA_PAM_SERVICE=noctalia-lock`

生成的 `/etc/pam.d/noctalia-lock` auth 段只有：

```text
auth sufficient pam_unix.so likeauth try_first_pass
auth required pam_deny.so
```

效果验证（错误密码结构测试）：Password 提示从 T+3536ms 提前到 T+1ms。

### 2. 降低密码哈希成本（已实施）

将 `vars/default.nix` 的 `initialHashedPassword` 从 scrypt
rounds=11（`$7$`）换成 yescrypt 默认 rounds=8（`$y$`）：

- scrypt rounds=11 单次验证：1741 ms
- 新 yescrypt 哈希单次验证：17 ms（本机实测，密码一致）

替换后解锁总时长约 0.1 秒（单次 pam_unix 验证 + 少量开销）。

操作：由本人在终端执行 `mkpasswd -m yescrypt -s` 生成新哈希，经 `crypt()`
往返校验确认与登录密码一致后写入 `vars/default.nix`（注释同步为
`generated by mkpasswd -m yescrypt -s`），再执行 `just local`。

注意：`users.mutableUsers = false` 且 `/etc/shadow` 在每次 activation 重新生成， `vars/default.nix`
里的哈希是 vitus 和 root 密码的唯一来源；替换后两台主机的登录密码即改为新哈希对应的密码（同一密码，无变化）。

## 安全权衡

- 专用锁屏服务不解锁 gnome-keyring：登录时 greetd 已解锁（`greetd.enableGnomeKeyring`），会话内 keyring 保持解锁，锁屏不解锁它无功能损失。
- yescrypt 默认 rounds 的离线暴力破解成本低于 scrypt
  rounds=11，但仍远高于在线攻击门槛（锁屏进程非特权、每次尝试仍需完整 PAM 流程）；本机登录主通道是 SSH
  key。

## 回滚方式

- 撤销 `NOCTALIA_PAM_SERVICE` 环境变量与 `noctalia-lock` 服务定义即恢复原 login 栈。
- 哈希如需回滚，把旧的 `$7$` 哈希写回 `vars/default.nix` 并 `just local`。

## 验证

